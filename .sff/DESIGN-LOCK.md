Three-tier honesty (added 2026-07-14, on user direction after 'how can this data be so wrong'): every signal is one of three tiers, visibly marked. MEASURED (unmarked) — straight from viberank / ccusage / GitHub (spend, tokens, commits, generations, cache mix, work-style, efficiency, ship-rate). SELF-REPORTED (teal 'you' tag) — truths the usage data can't reveal that the viber declared with `vibetracker profile --parallel-agents N --subs "..."` (real parallel-agent count, real subscription stack); these OVERRIDE the corresponding estimates. ESTIMATED (amber dashed 'est' tag) — reconstructed from partial data because Claude Code & Codex prune their logs (peak parallel agents, subscription footprint, ops ranking), shown only when no self-reported value exists. A legend explains each marker. MEASURE-AT-SOURCE: the CLI captures the ccusage token + per-agent breakdown at every upload (collectCodingTelemetry / `ccusage --by-agent`) before the logs prune, so token/agent data is measured going forward. Self-reported columns vibetracker_submissions.self_reported_agents / _subs (migration 012). Files: `lib/profile-signals.ts`, `profile-signals.tsx/.css`, `packages/cli/src/coding-telemetry.ts`. ## LOCKED

All thresholds + capacity references are documented constants, no per-user hardcoding. Pure engine `lib/profile-signals.ts` (unit-tested), panel `profile-signals.tsx`.
